Planning rule: every sprint ends with a working demonstration or a tested answer to a blocking question. The 13 slices below are a provisional sequence—not a promise to deliver the application in 39 days.

Phase 01 / Architecture proof

Make the core idea real.

A real harness, bounded observations, and durable follow-up work.

Recommended first commitment
SPRINT 013 days

A real agent leaves useful knowledge behind

OpenCode investigates a local fixture through an Effect MCP server. A fresh session understands the result.

  1. Day 1 · ConnectMinimal project, verified package pins, owned server/session, and the smallest useful adapter.
  2. Day 2 · IntegrateIn-memory asset, intent, observation, and finding tools; session credentials and server-side execution hook.
  3. Day 3 · DemonstratePositive and negative observations, denied action, fail-closed policy outage, and fresh-session briefing.
Done whenA second session chooses a sensible follow-up from recorded knowledge; a prohibited fixture action does not execute.

Boundary: hook integration does not prove control of arbitrary downstream shell or browser traffic.

SPRINT 023 days

The investigation survives a restart

Persist the same useful loop, with per-target isolation and trustworthy mutation identity.

  1. Day 1 · StoreControl and target SQLite files, static migrations, and identity rules for the fixture’s asset types.
  2. Day 2 · ConstrainMinimal domain records, anchoring, attempt authority, and persisted event-evolution rules.
  3. Day 3 · CommitDomain changes, receipts, events, and outbox entries in one transaction; verify exact and conflicting retries.
Done whenRestart preserves provenance. A retried mutation has one result. A superseded attempt cannot change current state.

Scope: minimal records and invariants—not the complete ScopeWeaver schema.

SPRINT 033 days

Committed work cannot disappear

Durable events and queued side effects drive subsequent work across interruption.

  1. Day 1 · ConsumeOrdered event reads, cursors, advisory PubSub wake-ups, startup catch-up, and reconciliation.
  2. Day 2 · DispatchOutbox claims, leases, delivery state, retry scheduling, and explicit effect replay policies.
  3. Day 3 · InterruptExercise transaction/delivery crash windows, missed wake-ups, and ambiguous external outcomes.
Done whenLost notifications lose no committed events. Outstanding effects survive. Unknown outcomes are not blindly repeated.
Checkpoint A

Delegated execution → useful knowledge → durable state → recoverable follow-up.

If this loop is awkward, improve it before adding more features.
Phase 02 / Investigation workbench

Make the loop useful.

Recover execution, preserve evidence, and turn bounded results into better investigations.

Provisional · Re-estimate after Phase 01
SPRINT 043 days

Recover a disconnected worker

Reconnect and reconcile actual harness state. Begin with one harness and one active worker.

DemonstrationDrop the event connection while work continues. Recover its outcome without launching duplicate work.
SPRINT 053 days

Capture evidence from Caido

Fetch referenced flows and store content-hashed evidence independently. Resolve Caido access/EULA questions first.

DemonstrationEvidence remains readable after its source flow disappears. Failed capture remains visibly incomplete.
SPRINT 063 days

Produce a trustworthy report

Generate from a fixed finding/evidence snapshot. Track whole-finding revisions and reject conflicting updates.

DemonstrationA qualifying finding update makes the old report stale. New limitations cannot be silently overwritten.
SPRINT 073 days

One planner. One worker.

Fresh planner rounds, deterministic briefings, bounded frontier, and explicit progress outcomes.

DemonstrationThe rate-limit fixture produces a narrow result, then a qualifying follow-up—without claiming an unlimited bypass.

Keep it small: referenced-flow ingestion, not a traffic browser; versioned report text, not dependency propagation; a bounded planner, not a scoring framework.

Checkpoint B

Record → preserve evidence → qualify a finding → report → investigate further.

A useful workbench for manually driven hunts, even before broader autonomous execution is ready.
Phase 03 / Unattended operation

Let it keep working.

Validate the perimeter, introduce cooperation, and recover available execution capacity.

Provisional
SPRINT 08Spike · Highest uncertainty

Validate the execution perimeter

Constrain the selected execution path beyond initial tool arguments. Choose the actual paths based on Sprint 1.

DemonstrationFixture tests cover redirects, subprocesses, and policy changes. Supported execution paths and limits are explicit.

May establish a constrained supported path rather than deliver a universal sandbox in three days.

SPRINT 093 days

Two workers cooperate

Persisted claiming, attempt-local workspaces, concurrency limits, steering, and stopping.

DemonstrationTwo workers cannot claim the same intent. Stopped or replaced attempts cannot continue authoritative mutations.
SPRINT 103 days

Recover from quota exhaustion

Same-harness fallback to an eligible model, or durable waiting when no capacity is available.

DemonstrationRecorded quota fixtures produce a reconciled replacement attempt or scheduled wait, without replaying uncertain actions.

Use recorded fixtures; do not deliberately exhaust a subscription just to test recovery.

SPRINT 113 days

Deliver Discord notifications

Route significant findings and blockers to dedicated channels within one server, using the existing outbox.

DemonstrationDelivery survives restart; failures are visible. Messages identify their source event and link to the app where available.
Phase 04 / Browser experience

See it. Operate it.

Two UI slices, each grounded in working application behavior.

Provisional
SPRINT 123 days

Observe a hunt in the browser

Targets, investigations, goals, intents, attempts, blockers, observations, and findings—with reconnectable event streaming.

  • Target and investigation overview
  • Observation and finding detail
  • Current attempts and blockers
  • Deterministic status queries
SPRINT 133 days

Operate and report from the browser

Start, pause/stop, and steer supported work. Inspect evidence, report freshness, worker activity, and notification delivery.

DemonstrationOperate one fixture investigation end to end without direct database access or development scripts.

Checkpoint C

A usable personal tool: autonomous planning, recoverable execution, evidence, reports, browser UI, and Discord.

Expand capabilities in response to actual use.
